
بناءً على اختيار "نظام نقاط الفني مسبقة الدفع" (Points/Credits System) كآلية أساسية ومحسنة لتحصيل العمولات، سنقوم بتحليل هذا النموذج وتكييفه ليتوافق مع المتطلبات التنظيمية والتشغيلية للسوق المصري.
يعتبر نظام النقاط من أفضل الممارسات عالمياً (مثل أنظمة Thumbtack وخطط أرصدة الشحن)؛ حيث يفصل بين المعاملات المالية الحقيقية (الجنيه المصري) والعمليات التشغيلية للتطبيق (النقاط)، مما يمنح المشروع مرونة ترويجية وقانونية كبيرة ويقلل من مقاومة المستخدمين لعمليات الدفع.

1. الركيزة القانونية والتنظيمية (Regulatory & Legal Compliance)
* تكييف النقاط: يتم تعريف النقاط قانونياً في شروط الاستخدام كـ "أرصدة استخدام رقمية غير قابلة للاسترداد النقدي المباشر" (Non-refundable Digital Credits).
* الامتثال للبنك المركزي المصري (CBE): لا يسمح النظام بسحب النقاط ككاش أو تحويلها بين حسابات الفنيين، مما ينفي عن التطبيق صفة "المحفظة المالية المفتوحة" ويجنبه التعقيدات الرقابية.
2. ركيزة تجربة المستخدم وتوليد العملاء (Zero-Friction Lead Generation)
* قيمة فتح البيانات: الفني لا يدفع مقابل "إتمام الخدمة"، بل يدفع "نقاطاً" لفتح بيانات عميل مهتم ومتحقق من هويته (رقم الهاتف والموقع التفصيلي).
* إخفاء التسريب (Anti-Leakage): يتم حجب أي بيانات اتصال أو عناوين تفصيلية في الوصف العام للطلب، وتصفيتها برمجياً لحين قيام الفني بعملية الفتح بخصم النقاط.
3. ركيزة حوكمة الاسترداد والنزاعات (Points Dispute Governance)
* الاسترداد بالنقاط: عند قبول أي نزاع (مثل رقم هاتف خاطئ أو عميل وهمي)، يتم رد "النقاط" مباشرة إلى المحفظة برمجياً في أجزاء من الثانية دون الدخول في معضلات استرداد الكاش عبر بوابات الدفع (Refund transactions)، وهو ما يوفر مرونة وسرعة استجابة فائقة للدعم الفني.

* الخطوة 1: تعديل الجداول البرمجية (Drizzle Schema): مواءمة الجداول لتدعم رصيد النقاط (points_balance) وفصلها محاسبياً عن المبالغ النقدية المدفوعة لشراء حزم النقاط.
* الخطوة 2: حماية العمولات عبر الـ Backend API: كتابة دوال تصفية نصوص الطلبات من وسائل الاتصال (Sanitization) قبل بثها للفنيين.
* الخطوة 3: ربط بوابات الدفع (شراء الحزم): ربط عمليات الدفع الحقيقية (Fawry / Paymob) بحزم النقاط (مثال: حزمة 100 نقطة بقيمة 100 جنيه).ويتم عمل شاشة لدي مسئول النظام لوضع تعريفات العمولات لكل تخصص او اضافة او تعديل العمولات المحصلة.
* الخطوة 4: أتمتة الاسترداد البرمجي (Refund Automation): برمجة محددات التحقق من النقر الفعلي على أزرار الاتصال لتسهيل قرارات الاسترداد الفورية.
* الخطوة 5: تعديل واجهات المستخدم (UI/UX): تحديث شاشات الفني لعرض الرصيد بالنقاط والتعامل مع عروض شراء حزم النقاط.

1. واجهة الفني (Technician Interface)
* شاشة المحفظة (Wallet Screen):
o إلغاء عرض العملة المالية (جنيه) في الرصيد الرئيسي، واستبدالها بـ "رصيد النقاط الحالي: X نقطة".

* الحزمة الأساسية: 100 نقطة مقابل 100 جنيه.
* الحزمة البرونزية: 250 نقطة مقابل 235 جنيه (توفير 15 جنيه).
* الحزمة الذهبية: 500 نقطة مقابل 450 جنيه (توفير 50 جنيه).

* شاشة تفاصيل الطلب بعد الفتح (Order Details - Unlocked State):

o تفعيل أزرار الاتصال السريع المدمجة: "اتصال مباشر" و "ارسل رسالة واتساب".
o إضافة زر هادئ في الأسفل: "أبلغ عن مشكلة في التواصل واسترد نقاطك" (يفتح شاشة إرسال بلاغ النزاع مع تبرير السبب).

2. واجهة العميل (Client Interface)
* لا يطرأ عليها تعديلات جوهرية، ولكن يتم إضافة نظام فلترة ديناميكي في حقول إدخال وصف المشكلة تمنع العميل من كتابة أرقام هواتفه في حقول النصوص وتنبيهه لضرورة كتابتها في الحقل المخصص للهاتف فقط لضمان الأمان وموثوقية الـ OTP.

3. لوحة تحكم مدير النظام (Admin Dashboard)
* مؤشر السيولة الملتزم بها بالنقاط (Points Liability): إجمالي عدد النقاط الموجودة في محافظ الفنيين حالياً والتي تمثل قيمة نقدية استلمها التطبيق ولكن لم يقدم مقابلها خدمة فتح بيانات بعد.
* شاشة إدارة طلبات الاسترداد (Dispute Resolution Screen): تظهر للمسؤول بيانات الاتصال بالطلب والتحقق التقني الآلي (هل نقر الفني زر الاتصال أم لا؟ كم مضى من الوقت قبل الإلغاء؟)، مع خياري: "قبول استرداد النقاط" أو "رفض الاسترداد" مع تبرير السبب للفني.

رابعاً: التعديلات الهيكلية على قاعدة البيانات (Upgraded Drizzle ORM Schema)
لتنفيذ هذا التغيير بدقة محاسبية متناهية، سنقوم بتعديل قاعدة البيانات بحيث:
1. يتم تخزين رصيد المحفظة بالنقاط (كعدد صحيح integer).
2. تتبع العمليات المالية الحقيقية (المبالغ المسددة بالجنيه وبوابات الدفع) بشكل مستقل في جدول حركات المحفظة، لتوثيق كيفية تحويل "الجنيه" إلى "نقاط" ومراقبة الأرباح.
codeTypeScript
import { 
  pgTable, 
  uuid, 
  timestamp, 
  varchar, 
  boolean, 
  text, 
  integer,
  numeric,
  pgEnum 
} from 'drizzle-orm/pg-core';
import { users } from './users'; // يفترض وجود جدول المستخدمين مسبقاً
import { orders } from './orders'; // يفترض وجود جدول الطلبات مسبقاً

// 1. تعريف الـ Enums لضمان سلامة العمليات المالية والتشغيلية بالنقاط
export const pointTransactionTypeEnum = pgEnum('point_transaction_type', [
  'package_purchase', // شراء حزمة نقاط بالجنيه المصري
  'lead_unlock',      // خصم نقاط لفتح بيانات عميل
  'dispute_refund',   // استرداد نقاط بسبب نزاع مقبول
  'admin_adjustment'  // تسوية يدوية بالنقاط من لوحة التحكم
]);

export const paymentStatusEnum = pgEnum('payment_status', [
  'pending', 
  'completed', 
  'failed'
]);

export const disputeStatusEnum = pgEnum('dispute_status', [
  'submitted', 
  'under_review', 
  'approved', 
  'rejected'
]);

// 2. جدول محفظة النقاط (Wallets) - تخزين الرصيد بالنقاط كعدد صحيح لسلامة الحسابات
export const wallets = pgTable('wallets', {
  id: uuid('id').defaultRandom().primaryKey(),
  userId: uuid('user_id').references(() => users.id, { onDelete: 'cascade' }).notNull().unique(),
  pointsBalance: integer('points_balance').default(0).notNull(), // رصيد النقاط الفعلي المتاح للاستهلاك
  updatedAt: timestamp('updated_at').defaultNow().notNull(),
});

// 3. جدول معاملات المحفظة (Wallet Transactions)
// يربط بين حركات النقاط والتدفق النقدي الفعلي بالجنيه المصري لشراء الحزم
export const walletTransactions = pgTable('wallet_transactions', {
  id: uuid('id').defaultRandom().primaryKey(),
  walletId: uuid('wallet_id').references(() => wallets.id, { onDelete: 'cascade' }).notNull(),
  
  // معالجة النقاط
  pointsAmount: integer('points_amount').notNull(), // قيمة موجبة في حال الشحن أو الاسترداد، سالبة في حال الخصم والفتح
  type: pointTransactionTypeEnum('type').notNull(),
  
  // معالجة النقد الفعلي (ملأ فقط في حالات شراء الحزم package_purchase)
  cashAmountPaid: numeric('cash_amount_paid', { precision: 10, scale: 2 }).default('0.00').notNull(), // المبلغ بالجنيه
  gatewayFeeCharged: numeric('gateway_fee_charged', { precision: 10, scale: 2 }).default('0.00').notNull(), // رسوم بوابة الدفع
  paymentStatus: paymentStatusEnum('payment_status').default('completed').notNull(),
  
  externalTxId: varchar('external_tx_id', { length: 255 }), // الرقم المرجعي لفوري / فودافون كاش
  description: text('description'), // تفاصيل توضيحية (مثال: "شراء الحزمة الذهبية 500 نقطة")
  createdAt: timestamp('created_at').defaultNow().notNull(),
});

// 4. جدول توثيق عمليات فتح الفرص بالنقاط (Lead Unlocks)
export const leadUnlocks = pgTable('lead_unlocks', {
  id: uuid('id').defaultRandom().primaryKey(),
  technicianId: uuid('technician_id').references(() => users.id, { onDelete: 'restrict' }).notNull(),
  orderId: uuid('order_id').references(() => orders.id, { onDelete: 'restrict' }).notNull(),
  pointsDeducted: integer('points_deducted').notNull(), // عدد النقاط التي خصمت لفتح هذا العميل
  
  // مؤشرات تقنية هامة لأتمتة الاسترداد والتحقق من النزاعات
  clickedCall: boolean('clicked_call').default(false).notNull(), // هل نقر الفني على زر الاتصال بالعميل؟
  clickedWhatsapp: boolean('clicked_whatsapp').default(false).notNull(), // هل حاول مراسلته واتساب؟
  unlockedAt: timestamp('unlocked_at').defaultNow().notNull(),
});

// 5. جدول حوكمة النزاعات واسترداد النقاط (Points Disputes)
export const disputes = pgTable('disputes', {
  id: uuid('id').defaultRandom().primaryKey(),
  leadUnlockId: uuid('lead_unlock_id').references(() => leadUnlocks.id, { onDelete: 'cascade' }).notNull(),
  reason: text('reason').notNull(), // سبب الاعتراض (العميل لم يستجب، الرقم غير صحيح)
  status: disputeStatusEnum('status').default('submitted').notNull(),
  adminNotes: text('admin_notes'), // رد مسؤول الدعم الفني
  pointsRefunded: boolean('points_refunded').default(false).notNull(), // هل أرجع النظام النقاط فعلياً للفني؟
  resolvedAt: timestamp('resolved_at'),
  createdAt: timestamp('created_at').defaultNow().notNull(),
});

خامساً: المزايا المحققة من هذا الهيكل المطور
1. الوقاية التامة من استدعاءات الاسترداد النقدية البنكية (Refunds Chargeback): عند حدوث مشكلة أو نزاع مع فني، يُعاد الرصيد كـ "نقاط" داخل التطبيق فوراً وبضغطة زر برمجية دون لمس حساب البنك أو بوابة الدفع الخاصة بك، مما يوفر استقراراً مالياً هائلاً.
2. المرونة التسويقية (Gamification): يمكنك بسهولة عمل حملات تسويقية وتوزيع هدايا للفنيين الجدد (مثال: "سجل اليوم واحصل على 30 نقطة ترحيبية مجانية لفتح أول عمليتين").
3. الامتثال التام للبنك المركزي المصري: التعامل بالنقاط الرقمية غير القابلة للاسترداد المباشر كاش يخرج التطبيق محاسبياً وقانونياً من تصنيفه كـ "شركة وساطة مالية" ويضعه في خانة "بيع السلع والخدمات الرقمية الاستهلاكية".
